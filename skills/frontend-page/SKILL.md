# 前端页面编写

你的任务是产出一份**单文件 HTML 页面**（内联 CSS/JS），并用 open_preview 在浏览器中打开给用户看。渲染效果是最终交付物，代码本身不是。

**能力边界（交付时必须向用户声明）**：你无法观测渲染结果——open_preview 只是把页面在浏览器打开，动画是否流畅、hover 是否生效、移动端布局是否正确，都只能由用户肉眼确认。交付时附一句"视觉效果请你在浏览器里确认，有不满意的告诉我改"。

## 硬性约束

1. **单文件**：一个页面 = 一个 `.html` 文件，CSS 和 JS 全部内联。除非用户明确要求，不拆文件、不引外部框架（不用 React/Vue/Tailwind）。
2. **零外部依赖**：不引用任何 CDN、字体库、图标库。图标用 emoji 或内联 SVG，字体用系统字体栈。**图片一律用 emoji / 内联 SVG / CSS 渐变占位块，禁止外部图片 URL**（picsum、unsplash 等），除非用户明确提供了本地素材路径。
3. **文件位置**：写到当前工作目录下（如 `index.html`、`profile.html`），文件名用小写英文。
4. **本地素材路径约束**：open_preview 的服务根是 **HTML 文件所在目录**，`../` 会 404。因此页面和它引用的本地图片等素材必须在同一目录或其子目录下（如页面 `cake-shop.html` 引用 `images/cake.jpg`，则图片放 `./images/`，页面里写相对路径 `images/cake.jpg`）。素材在别处时，先把素材复制到页面目录旁，不要用 `../` 引用。

## 内容真实性

- 用户提供的真实信息（姓名、经历、项目、数据）优先使用，不得改写或遗漏。
- 自行补全的内容分两档处理：
  - **必须留 TODO 占位，禁止编造**（承诺性/联系性事实，编了会误导）：地址、电话、邮箱、ICP 备案号、资质证书、获奖记录、营业时间、人数/成绩等统计数字、具体日期。写 `<!-- TODO: 替换为真实XX -->`。
  - **可以自拟，但必须声明为示例**（可替换的展示内容）：店名/标题、产品名称、价格、广告文案、评价内容、示例数据。写完后告诉用户"店名、产品、价格、评价是占位示例，请替换成真实信息"。
- 用户消息里出现真实信息时，上面两档都优先用真实值。

## 页面骨架（必须遵守的结构起点）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>页面标题</title>
<style>
  :root {
    --bg: #0f1115;          /* 页面底色 */
    --surface: #1a1d24;     /* 卡片/区块底色 */
    --text: #e8eaed;        /* 主文字 */
    --muted: #9aa0a6;       /* 次要文字 */
    --primary: #6c9ef8;     /* 主题色（渐变起点） */
    --accent: #a78bfa;      /* 渐变终点 */
    --on-primary: #ffffff;  /* 主题色上的文字色（按钮文字等） */
    --border: rgba(255, 255, 255, 0.08);  /* 细边框/分隔线 */
    --primary-rgb: 108, 158, 248;  /* 主题色 RGB 三元组，供 rgba() 透明度变体 */
    --accent-rgb: 167, 139, 250;   /* 渐变终点的 RGB 三元组，同上 */
  }
  * { margin: 0; padding: 0; box-sizing: border-box; }
  body {
    font-family: -apple-system, "Segoe UI", "Microsoft YaHei", sans-serif;
    background: var(--bg);
    color: var(--text);
    line-height: 1.8;
  }
</style>
</head>
<body>
  <!-- 页面内容 -->
</body>
</html>
```

## 风格规范

- **主题色调性**：深色主题为默认；但行业调性明显偏浅色的（餐饮、母婴、婚礼、烘焙、医疗等），可以改用浅色底——改时同步调整 `:root` 里全部变量值，并在交付时说明"按行业调性选了浅色"。
- **主视觉**：标题区可用 `linear-gradient(135deg, var(--primary), var(--accent))` 渐变文字或按钮
- **布局**：内容区最大宽度 960px 居中；多列内容用 CSS Grid，卡片间距 24px
- **卡片**：`background: var(--surface)` + `border-radius: 16px` + `padding: 28px` + 细边框 `1px solid var(--border)`
- **响应式**：断点统一用 768px（覆盖手机竖屏），`@media (max-width: 768px)` 折叠为单列；只需保证 480px 宽度下已是单列且无横向溢出，不要另设 480px 断点
- **交互**：所有可点击元素必须有 `transition: 0.2s` 和 `:hover` 反馈（变亮或上浮）
- **动效克制**：装饰性动画（漂浮、循环渐变）最多 1-2 处；必须带降级规则：
  ```css
  @media (prefers-reduced-motion: reduce) {
    * { animation: none !important; transition: none !important; }
  }
  ```
- **排版**：中文正文 15-16px；标题加粗且层级分明（h1 用 clamp() 控制响应式字号）
- **颜色纪律**：颜色一律走 `:root` 变量——纯色用 `var(--primary)` 等，半透明用 `rgba(var(--primary-rgb), 0.15)` / `rgba(var(--accent-rgb), 0.10)`；不写主题色字面值。骨架已提供 `--primary-rgb`/`--accent-rgb`/`--on-primary`/`--border`，需要新的透明度变体时先确认 `:root` 里有没有对应 rgb 变量，没有就补进 `:root` 再用。

## 工作流程（严格按顺序）

1. 理解用户要的页面类型和内容要点；信息不足时基于常见场景合理补全（遵守上面的内容真实性规则），不要反问拖延。
2. 按骨架和规范写出完整 HTML，调用 `mcp_filesystem_write_file` 写入文件。
3. **落盘自查**：写入成功后用 `read_file` 回读文件头部约 20 行，确认文件真实存在且开头完整（charset、:root 变量在），再继续。
4. **写完必须调用 `open_preview` 打开页面**——这一步不可省略，用户需要看到渲染效果。
5. **交付说明**：告诉用户（a）哪些内容是自拟示例需要替换；（b）哪些地方留了 TODO 待补真实信息；（c）视觉效果请用户在浏览器确认。
6. 用户提出修改意见（颜色/布局/内容）→ 修改文件 → 再次 `open_preview`。

## 异常处理

### 写文件失败（write_file 报错 / 审批被拒绝）

- **审批被拒绝**：不要换路径重写。问一句用户希望写到哪，或确认用户是否只想看代码不落盘；按用户答复继续。
- **路径/权限类错误**：换成当前工作目录下的新文件名（如 `index-2.html`）重试一次；再失败就把完整 HTML 作为代码块直接输出在对话里，说明"文件未能写入，可手动保存"，然后尝试 `open_preview` 预览工作目录。

### open_preview 失败（服务起不来 / 浏览器打不开）

- 失败信息里带有页面 URL → 把 URL 告诉用户，请他手动在浏览器打开，不要反复重试。
- 连 URL 都没有（服务启动失败）→ 检查目标文件是否真的存在（用 `list_files` 确认）；文件在就把 `http://127.0.0.1:端口/文件名` 的格式建议给用户。**最多重试一次**，仍失败就转为"代码已交付 + 手动打开指引"，不要陷入重试循环。

### 内容与页面复杂度

- 页面超过约 **700 行**时按信息密度精简：优先合并重复样式、抽取公共 class，**不删实质内容**；装饰性动效次之。单文件不是单屏，内容多时用锚点导航分节。
- 用户要求的功能明显超出静态页面能力（后端存储、登录、实时数据）→ 直接说明单文件静态页做不到的部分，并给出纯前端能实现的最接近方案（localStorage 模拟、示例数据硬编码），不要引入框架或伪造功能。

### 修改请求的边界

- 小改动（颜色、文字、间距）→ 直接改文件重新预览，不重写整页。内联样式里引用 `var(--xxx)` 是允许的（不算违反无内联 style 要求），方便局部微调。
- 结构性改动（换布局、加整块内容）→ 修改前先说一句计划改什么，避免改坏已确认的部分。
- 用户说"全都不对/重做" → 重写前确认保留哪些元素；无法确认时按原要求从头生成新文件（如 `index-v2.html`），旧文件留着不覆盖，让用户对比。
- 修改后**必须**再次 `open_preview`，让用户看到改动效果——"改了但没展示"等于没改。
- 页面里的示例链接（导航、按钮跳转）用页面内锚点 `#section`，不要指向不存在的 URL；预览服务的地址只在本次运行期间有效，agent 退出即失效，不要把预览 URL 当作长期交付物写进文档或代码注释。

## 交付前自检

- [ ] `@media (max-width: 768px)` 折叠为单列，480px 宽度下无横向溢出
- [ ] 所有可点击元素有 hover 反馈；有动画时带 `prefers-reduced-motion` 降级
- [ ] 颜色全部走 `:root` 变量（含半透明变体），无写死的主题色字面值
- [ ] 无外部 CDN 引用、无外部图片 URL；本地素材用同目录/子目录相对路径（无 `../`）
- [ ] 承诺性事实（地址/电话/资质/日期等）均为 TODO 占位而非编造；自拟的示例内容（店名/产品/价格/评价）已准备向用户声明
- [ ] 页面标题 `<title>` 与内容匹配；`<head>` 里有 `<meta name="description">`
- [ ] 中文内容无乱码（确认 meta charset）
- [ ] 落盘自查已做（回读文件头确认写入成功）
- [ ] 交付说明已准备（示例内容清单 + TODO 清单 + 请用户确认视觉效果）
